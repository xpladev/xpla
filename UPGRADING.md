# Upgrading XPLA

## v1.11

The v1.11 binary upgrades Cosmos SDK, Cosmos EVM, and IBC-Go together. Treat
the binary switch as a coordinated consensus upgrade and complete the checks
below before the upgrade height.

### Node configuration

XPLA used the Cosmos EVM application mempool before v1.11 and migrates that
path to Krakatoa in v1.11. Existing `config.toml` files are not regenerated by
installing a new binary. Every validator and full node running CometBFT in
process must set:

```toml
[mempool]
type = "app"
```

Existing `app.toml` files can still contain the old SDK default that disables
the application mempool. XPLA does not support disabling this path in v1.11, so
also update the top-level `app.toml` mempool section before starting the new
binary:

```toml
[mempool]
max-txs = 0
```

`max-txs = 0` keeps the application mempool unbounded. A positive value limits
the number of transactions retained by the application mempool. Any negative
value, including `-1`, is unsupported and causes the node to fail during
startup.

The Cosmos EVM server cross-validates this setting against the application
mempool configuration and refuses to start when an enabled application
mempool is paired with `type = "flood"` or `type = "nop"`.

### Cosmos EVM v0.7 state compatibility

Cosmos EVM v0.7 does not define a module schema migration for the v0.6 to v0.7
upgrade. The `v1_11` handler therefore does not rewrite existing EVM
parameters, activate newly available static precompiles, or install default
preinstalls. Existing on-chain EVM state remains unchanged across the binary
upgrade.

The v0.7 defaults used when creating a new genesis are not applied
retroactively to a live chain. Enabling the ICS02 precompile, installing
default preinstalls, or otherwise changing EVM parameters requires a separate,
explicit chain decision and its own compatibility checks.

### Feegrant expiration queue state compatibility

The v1.10 feegrant keeper stored expiration-queue entries as keys with empty
values. Cosmos SDK v0.54 reads the same queue through a collections map whose
canonical boolean value is one byte. XPLA installs a backward-compatible value
codec for this queue: legacy empty values decode as the presence marker `true`,
while newly created entries retain the canonical one-byte encoding.

This compatibility path must remain enabled while any pre-v1.11 fee allowance
with a future expiration can remain on chain. The incompatibility is latent at
the upgrade height because the end blocker only decodes queue entries after
their expiration becomes eligible for pruning.

### IBC-Go v11.2 state migration

The live v1.10 chain stores packet-forward middleware and rate-limiting state
under the following legacy `ibc-apps` keys:

- packet-forward middleware: `packetfowardmiddleware`
- rate limiting: `ratelimit`

IBC-Go v11.2 deliberately reuses both keys. Do not add, rename, or delete
either store in `StoreUpgrades`. The `v1_11` handler passes the live module
version map to `RunMigrations`, which performs the following in-place changes:

- packet-forward middleware 3 to 4: rewrites in-flight packets without the
  deprecated `nonrefundable` field. The migration aborts if any stored packet
  has `nonrefundable = true`.
- rate limiting 1 to 2: removes legacy pending send and receive markers because
  their keys do not contain a denomination. Existing flow remains charged
  until its next quota reset; all other rate-limit state is retained.

Before scheduling the upgrade, inspect a production state copy for
nonrefundable packet-forward entries and let those packets finish or otherwise
resolve them. This state is not exposed by a complete public query, so perform
the check against a node database or an equivalent state export. Rehearse the
handler against the same state copy before mainnet activation.

IBC-Go v11 requires address codecs in the transfer, packet-forward, and
rate-limiting keeper constructors. XPLA supplies the account keeper codec to
all three. ICS27-GMP is not integrated in XPLA, so the optional GMP store from
the IBC-Go v10 to v11 guide is intentionally not added.
